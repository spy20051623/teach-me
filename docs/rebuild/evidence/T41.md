# T41 · helper混合请求期限隔离

2026-10-22。用户检视指出3秒短查询timeout会终止原本10秒的窗口操作。当前windows.ts确实在任意请求timeout调用close(helper)，将整代pending全部结算；不是单个窗口操作自己的期限到达。

目标：短请求按自己的期限结束，尚未到期的请求保留响应机会；卡死helper有界淘汰，持续轮询不能无限延长旧代；不重放可能已执行的窗口操作，旧回包不得影响替换代。先用FakeChild/模拟时钟保留失败对照，再回归与独立审查。沿用不做实机的限制，不启动App或原生helper；Windows慢启动/焦点等实际验收保留pending。

失败对照：inputPolicy与foreground/talkDown同时挂起，在helper未READY及已READY两种状态均于3秒使input提前NATIVE_TIMEOUT；原12项通过，新2项失败（.runtime/t41-before.log）。修复后3秒只结束查询，4秒input成功才淘汰；共18项helper测试通过，包含恢复期持续轮询/窗口新请求不写入旧管道、style读超时保护后来的input、窗口写超时硬淘汰、dispose立即结算、旧回包/退出/计时器隔离。

实现与取舍见ADR-031。独立审查运行18项通过，未发现阻断；证据只承诺draining期间不启动替代helper，不把kill()称为已确认进程退出。此次修复覆盖已复现P2调度逻辑，不证明T14静置退出或历史首次启动10秒失败根因。Windows实机因本轮限制保留pending。
