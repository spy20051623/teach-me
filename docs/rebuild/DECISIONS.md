# 架构决策记录

## ADR-001 · 接受 · 2026-10-17 · 独立重建

用户认可现有设计/交互，但希望避免在旧实现上持续补丁，并明确要求新建空分支。采用孤立分支 codex/companion-rebuild-empty，从 f5e1e56 建立根工程，React + TypeScript + Vite，CSS token + 共享组件，不引入 Tailwind。旧应用只保留在另一分支；随时可回到快照 54623c6，新分支不恢复旧 main.js。

## ADR-002 · 接受 · 2026-10-17 · 状态语义修正

Agent 状态使用 offline/ready/waiting/thinking/ended；语音状态独立。waiting 表示等待用户消息，应允许继续；录音或草稿非空时隐藏继续。所有 scene 内容都计入指引存在性；用户画板附件仍只表示笔迹层。这修正原 notes 中将“在听”视为忙碌、将 board.agent 作为全部指引判据的实现约定。

## ADR-003 · 待验证 · 2026-10-17 · 鼠标入口的聚焦前截图

约束已确定：不能在 textarea focus 以后才保存原软件；不能把已经聚焦自己的窗口当作“原软件”。候选实现：宿主跟踪最近的外部前台窗口，在非激活面板入口准备输入，记录帧后显式激活输入。需要验证从非激活窗口到可编辑面板的时序；仅仅阻止浏览器 pointerdown 默认行为不能证明原生窗口未激活。

M2 必须先做 Windows 小实验，记录鼠标与全局快捷键路径的窗口句柄、截图时间、激活时间、发送与取消后的前台窗口。不满足 R03 时不能靠改文档为“发送时截图”绕过。

## ADR-004 · 接受 · 2026-10-17 · 规划即工程文件

tasks.json 为状态唯一来源；需求、验收、ADR 与证据随实现提交。检查器拒绝未知引用、循环依赖、缺失完成证据、依赖未完成却 done。CI 执行同一检查；禁止只有聊天记录宣称完成。

## ADR-005 · 接受 · 2026-10-17 · 远控可见性

用户要求在虚拟屏／远程控制画面里看见应用。原实现对所有窗口无条件调用 setContentProtection(true)。新增 showInScreenCapture 配置及设置页开关，开启时统一关闭面板、画布与 HTML 的内容保护；保存后立即应用，新 HTML 窗口继承。旧配置缺省 false，继续保护；本机按用户要求配置为 true。应用自己的 captureScreen 仍先临时隐藏应用窗口，因此该开关不决定 Agent 截图是否包含指引。

此变更控制应用是否允许被捕获，不安装虚拟显示驱动，不保证所有第三方远控采集方案兼容；真实客户端画面尚未验证。

## ADR-007 · 接受 · 2026-10-17 · 取消取图显隐与真实 CLI 验证

用户反馈上一轮升级后仍闪烁、无回复。ADR-006 的缩短隐藏时间不能消除 hide/show，废止该取图方案。改为取帧前对面板、画布、HTML 临时启用系统捕获排除，finally 恢复用户的远控可见设置；不隐藏窗口、不改焦点。显式启用 Chromium AllowWindowCaptureExclusionInRemoteSessions，避免 Electron 44 某些版本远程会话中内容保护被忽略。不同远控方案仍须实测，不能只用 isContentProtected 推断画面已排除。

CLI 从 fetch 改用 node:http，八分钟长轮询仅受明确请求期限约束，不再受独立响应头期限限制。既有测试只调用 API，不能代表命令行完成端到端验收；新增真实 CLI 子进程两轮 UI→wait/ack→say，以及超过五分钟无响应头后再收消息的实验。未证实上次 fetch failed 是超时还是应用退出，不写成已定位唯一根因。

增加有大小上限的本地 runtime.log，只记录启动/退出原因、进程退出、wait 开始/完成及消息数量；不记录文字、截图、路径或 token，不提交到 Git。用于区分应用退出和网络等待失败。

## ADR-006 · 取图方案已由 ADR-007 取代 · 2026-10-17 · 输入去重与连接存活提示

prepare 的并发调用共用一次记窗/取图/聚焦，已有编辑回合仅重新聚焦，不重复截图。窗口仅在取帧期间隐藏，35ms 合成等待后取帧，随后立即恢复；缩放、PNG 编码与写盘在可见状态执行，失败也恢复。保留截图排除自身的约束，因此单次取帧仍可能短暂闪一下，不能宣称零闪烁。面板缓存实际高度，同尺寸不重复 setBounds，HTML 可见状态未变时不重复 showInactive。

Agent 必须持续 wait，超时后再次 wait；单次 wait 结束不意味着后台仍有人自动回答。宿主在无活跃 wait 且 ready 超过 15 秒、thinking 超过 5 分钟时显示 offline（文案为连接待确认），保留未确认消息；新的 wait/say 恢复状态。这是活动超时判断，不是进程存活证明。活跃长轮询不触发过期。

## ADR-008 · 接受 · 2026-10-17 · 将任务栏身份与输入焦点分开

Electron Windows 的 SetFocusable 同时调用 SetSkipTaskbar(!focusable)，原先输入/发送/设置/画板切换会改变任务栏入口。仅紧接着 setSkipTaskbar(false) 在本机现场仍会在失焦后消失，不能作为修复完成。主面板明确使用 WS_EX_APPWINDOW、清除 TOOLWINDOW，画布明确使用 TOOLWINDOW、清除 APPWINDOW，再应用任务栏入口策略。保留 NOACTIVATE 位以维持聚焦前取图，更新样式不激活、不移动、不改 Z 序；异步平台调用之后检查 turn 是否仍有效。

主面板在活动与非活动状态均保留一个任务栏入口；画布与 HTML 不参与任务栏。快捷键没有创建窗口的路径，用句柄、渲染 PID 和 browser-window-created 计数验证复用。启动时设置角色，后续每次焦点切换均重申策略。设置与画板不因可聚焦而成为新的任务栏窗口。来源：[Electron SetFocusable 实现](https://github.com/electron/electron/blob/main/shell/browser/native_window_views.cc)、[Microsoft 扩展窗口样式](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles)。

## ADR-009 · 接受 · 2026-10-17 · 稳定激活代理与浮窗层级

ADR-008 仍在每次输入切换 Electron setFocusable，Windows 会连带删除/添加任务栏入口。现在面板和画布的 Electron 激活代理从创建起保持可激活，实际鼠标激活由宿主 Win32 NOACTIVATE 位控制，任务栏角色只在首次/角色变化时应用，不在每次输入重建。取帧前保持 NOACTIVATE，取帧后解除；系统拒绝普通 focus 时使用原生前台激活兜底，再聚焦 WebContents。取消或旧异步回调按 turn 检查，不得让旧输入重新占据焦点。

面板和画布不提供常规最小化；热键在确实已最小化/隐藏时恢复同一个窗口。外部前台窗口变化时仅提升已可见、未最小化的原浮窗 Z 序，不调用 show/hide、不激活；恢复外部窗口只使用 SetForegroundWindow，不再冗余 BringWindowToTop。新增无正文窗口生命周期日志，用于区分 hide/minimize 与崩溃/退出。

## ADR-010 · 接受 · 2026-10-17 · 主线替换

用户本轮明确授权修复后备份原 master、将当前重建分支变成 master 并推送，该授权覆盖平时“不自动 push”的默认约定。先 fetch 并记录 origin/master 原 SHA，先推独立备份并核对，再以该 SHA 为 lease 更新 master；远端有并发变更即停止替换并重新处理。此次提升主线不表示所有产品任务已经验收，待验证任务继续留在 tasks.json。

## ADR-011 · 接受 · 2026-10-17 · 复用 Excalidraw 用户编辑器

用户明确指出用户自己的画板能力不足，并要求优先借用开源项目。选择 MIT 许可的 `@excalidraw/excalidraw` 0.18.1（支持 React 19），以本地 React 组件接入透明屏幕画板。tldraw SDK 的生产使用需要额外许可，不采用。许可与版权保留在 THIRD-PARTY-NOTICES.md，字体与其 notices 随构建复制；依赖和兼容修复 overrides 写入锁文件。

保留 Excalidraw 自带的编辑工具、选择、样式、撤销和缩放；仅编辑时展示界面并接收鼠标，完成后保留实例、隐藏界面并穿透。离线可画，首次连接同一屏幕时保留预先绘制内容；替换旧会话时清除。用户内容和 Agent 场景分层；主进程不导入第三方场景格式，仅校验来自 overlay 的数量/epoch。用户画板清除会重置其历史，不能用旧撤销或晚回调恢复清除前内容。发送透明屏幕坐标 PNG，独立合成 Agent 笔迹，不截取编辑器 UI。图片/文本等编辑数据在 renderer 内存持有，不写配置或 Git。

包按需加载；字体本地打包。0.18.1 即使设置本地路径仍追加字体 CDN fallback，构建适配将该 fallback 改为同一本地路径，CSP 继续阻止远程资源；禁用 AI、外部嵌入、外链打开和在线协作入口。手动选择库、图片导入等附加流程未验证，不扩展声称。

依据：[MIT 许可](https://github.com/excalidraw/excalidraw/blob/master/LICENSE)、[官方集成方式](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/integration)、[官方导出 API](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/utils/export)、[tldraw 许可](https://tldraw.dev/community/license)。

## ADR-012 · 接受 · 2026-10-18 · 可移动 mini 输入面

收起宽 360 DIP、空态约 76 DIP，展开宽 520 DIP；多行输入自动增高，始终复用同一 textarea。状态栏保留拖动把手与展开入口，语音/画板/发送使用图标，附件/清理/设置收进可增高的“更多”，不使用会被原生窗口裁掉的悬空菜单。

Windows 实验中 CSS 原生拖动区域存在但窗口未随鼠标移动，因此标题区用 Pointer Capture 接收手势。Renderer 只通过固定 panel-drag 白名单发送手势 id 与屏幕 DIP 位移；主进程校验范围、绑定原窗口起点、忽略结束后的晚回调，按钮和输入区不启动拖动。不发送窗口句柄，不改变现有 NOACTIVATE/截图/任务栏策略。位移随事件采样，避免 IPC 延迟导致主进程事后读取鼠标位置而丢失起点。ResizeObserver 带收起状态，过时尺寸报告不跨模式应用。

宿主在本地 panel-position.json 保存屏幕 id 和右下锚点，独立于教学屏幕；展开/收起向左上增长，不能容纳时限制在工作区。显示器移除或布局变化时回退到可用屏幕并夹紧；负坐标/小工作区由纯几何测试覆盖，多屏不同缩放的实际拖动仍须真机另验。配置和截图均不进 Git。

参考：[Electron 官方拖动区域说明](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)。CSS 区域通过不替代 Windows 实际拖动通过。

## ADR-013 · 接受 · 2026-10-18 · 三档面板与情境切换

用户追加双入口小胶囊参考图；将 ADR-012 的360宽布局保留为中号，默认小号120×48，大号520。具体切换矩阵、保护条件与阅读时间见 [PANEL-MODES.md](PANEL-MODES.md)。状态策略在 core，宿主负责计时/原生尺寸与焦点，renderer只报告草稿存在性、工具打开与减少动态效果偏好；保留唯一输入。回复不打断用户编辑；审批必须可见；悬停不放大，空闲才收小。

Windows 通过宿主200ms插值同一窗口尺寸实现过渡；更新的目标替换旧目标，拖动前结束动画。设置与系统减少动态效果受尊重。依据：[Electron setBounds API](https://www.electronjs.org/docs/latest/api/browser-window#winsetboundsbounds-animate)、[W3C 交互动画与减少动态效果](https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html)。这些资料支持实现与可访问性边界；切换时机是本项目设计决议。

## ADR-014 · 接受 · 2026-10-18 · 从实际试用修复入口、阅读与输入布局

用户要求实际试用并找出优化点。原生试用复现三项问题：无会话写字只显示错误且标题误导、旧消息阅读被新回复拉到底部、长历史加长草稿裁掉底部工具。无会话的 prepare 改为打开连接帮助，不开始取图或输入事务；已存在但断联的会话仍沿用原有队列与恢复语义。复制连接说明是主进程固定白名单动作，renderer 不提供任意剪贴板内容，说明不含 token。

对话默认跟随底部；用户上翻后记录阅读位置，新 Agent 回复只增加提示计数。点击提示或用户主动发送回到底部并恢复跟随；打开设置后返回也恢复位置，换会话重置。面板最大高度继续受约束，正文区域可收缩滚动，输入和发送占据固定的底部空间；标题保持设计决议中的一行摘要。三档状态策略与唯一输入实例不变。

后续优化方向按证据/T18 的实际观察排序；画板持久化尚无产品决议，本次不改变其内存生命周期。工程回归与原生操作证据分开记录，不据此关闭语音、IME、多屏或完整视觉验收。

## ADR-015 · 接受 · 2026-10-18 · 项目即记忆

用户明确要求将“项目即记忆”作为必要的工程能力。延续 ADR-004：意图、取舍理由、任务、失败经验、验收证据和下一步都随 Git 演进，新 Agent 不依赖旧聊天或个人私有记忆。根 AGENTS/MEMORY 为强制入口；已有 PRODUCT/DECISIONS/ARCHITECTURE/ACCEPTANCE/evidence 各自承担原有职责，不另建平行知识库。

tasks.json 仍是状态唯一来源，新增 nextUp 引用任务、记录优先理由和具体动作；检查拒绝未知/重复/已完成/依赖不满足的接续任务。CONTEXT.md自动生成任务视图与接续顺序，不手工复制状态；PROGRESS整理为简短当前接续，旧正文完整归档，不覆盖历史证据。优先队列可由用户新要求改变，候选建议不能未经决议自动变成产品承诺。

生成器对规范入口、源代码、测试、规划、CI和依赖声明计算确定性摘要，排除自身输出、Git元数据和运行目录，文本统一行尾。context:check只读，不静默修复；变更后显式context并审阅，然后check。纳入现有CI的npm run check，不新增后台服务、数据库、向量检索或对话抓取。

为什么不仅加一篇说明：入口文档解决检索，任务视图减少复制状态，源摘要让代码/证据变动后未刷新摘要可被发现，归档避免新旧结论混读。同步检查不能判断Agent是否真的写全原因或做过验收，必须保留人工审阅和真机证据边界。维护细则在根 MEMORY.md；中断也要留下未完成项和下一步。

## ADR-016 · 接受 · 2026-10-19 · 连续过渡与独立设置窗口

用户反馈三档变化没有动画感，希望设置弹出窗口。现有T17自动帧测试通过，但模式结束后的内容测高直接改原生高度，目标内容即时重排；自动中间帧存在不能证明体验无跳变。以本条修正ADR-013的200ms/静止后测高策略：采用280ms过渡，目标布局在固定目标宽度测量，背景随原生窗口连续变化；当前档位测高可重新定目标，动画从当前帧继续，重复目标不重启，减少动态效果依旧直切。

设置使用预建、隐藏的独立普通BrowserWindow，首次打开即复用实例，独立标题与系统边框，可拖动/调整大小；不替换对话，不改变主面板档位、尺寸或输入实例。打开时暂停自动收小，关闭隐藏该窗口、丢弃未保存设置；原消息草稿保留，编辑中的输入恢复聚焦。正文独立滚动，保存/取消固定在底部；异步保存成功后关闭，失败保留表单与错误。写盘成功后才替换运行配置，避免失败后内存配置偷偷生效。

设置窗口沿用隔离preload，sender只允许settings/settings-focus/select-display；不挂载教学输入/麦克风组件，不能发送prepare/quit/board-change等动作。内容保护及应用取图排除同样覆盖设置窗口。默认系统设置不变；本轮只验证单屏，跨屏行为另验。实现依据：[Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)。

现场曾出现首次show后收到focus事件、但isVisible为false且系统窗口列表没有设置窗口；改为show后检查可见性，必要时showInactive再focus，重跑原生入口与自动回归通过。最小实验也复现首个普通窗口的该现象。[Windows ShowWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow)说明启动信息会影响首次显示请求；它与隐藏启动器有关是推断，不能据此宣称已定位T14的历史进程退出根因。标题栏使用系统边框；系统菜单移动已观察到位置改变，鼠标拖动尚未验证通过，见T20。

## ADR-017 · 接受 · 2026-10-19 · 合成过渡、无框标题与外观扩展

用户纠正T20动效仍卡、系统标题框不美观，要求亮暗色与未来主题/桌宠。替代ADR-016的逐帧原生尺寸插值及系统标题栏：原生窗口先分配包围范围，Chromium以220ms transform/opacity/clipPath完成视觉过渡，结束收紧；原A22/A25的“原生尺寸中间帧”要求由A26的视觉连续帧/有限原生写入取代。不能以存在动画帧否定用户反馈，也不能仅延长动画时长解决透明窗口resize重绘。

设置使用frame:false的普通不透明窗口，保留原生边缘调整大小，顶部与内容统一配色、关闭按钮独立。原生app-region拖动实验未移动，改用主面板已有的Pointer Capture与限定sender动作，拖动id/工作区约束/关闭后清理；保存初始客户区尺寸防分数DPI移动累积变大。系统首次show的可见性回退继续保留。

颜色模式与主题id独立存储；旧配置默认深色，设置内预览，保存后跨窗口应用。内建主题注册表集中完整语义token，画板使用库的theme属性保留内容；原生主题事件只在跟随系统时更新外观。桌宠作为后续独立表现层，复用现有状态与单一输入，不把资产包变成执行权限。契约和分阶段范围见[APPEARANCE.md](APPEARANCE.md)。

实现参考：[Electron无框窗口](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)、[nativeTheme](https://www.electronjs.org/docs/latest/api/native-theme)、[Element.animate](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate)。保留thickFrame以支持边缘调整；禁用它会失去该能力，见[BaseWindow](https://www.electronjs.org/docs/latest/api/base-window)。

## ADR-018 · 接受 · 2026-10-19 · 稳定终点与拖动尺寸所有权

用户反馈T21完成时偶闪、移动放大。故障注入确认旧背景基于动态原生包围范围缩放，原生先收紧而旧效果未清理时会再次缩小；拖动中测高虽未立即setBounds，仍改了缓存高度，释放时应用并再反向动画；此外本机125%下setPosition自身回读高度逐次增大。不能将这三项归结为动画时长或主观感受。

背景以固定目标宽高做FLIP，终点为identity，锚点随视口收紧保持；拖动进入前先冻结形变/尺寸所有权，固定逻辑宽高平移。测高引入panelLayoutVersion，跨模式与拖动边界作废，拖动中不写缓存；释放后重新测当前布局。用故障注入检查原生先收紧、迟到测高和连续拖动中的瞬态，补足T21只收集中间帧的遗漏。

本条修正ADR-017的终点/拖动实现，保留同HWND、单输入面、主题与设置方案。公开最佳实践、具体采用与能力边界见[MOTION.md](MOTION.md)，证据见T22。

## ADR-019 · 接受 · 2026-10-19 · App、全局CLI与可安装教学skill

## ADR-020 · 接受 · 2026-10-19 · 英文公开入口与中文README

## ADR-021 · 接受 · 2026-10-19 · Agent无关定位与显式技能安装入口

用户纠正README将Codex描述得过于具体，强调项目Agent无关，且skill安装不明显。现有本地CLI/协议并不要求特定Agent；此前README先放开发/规划，再以Codex便捷安装为默认阅读路径，混淆了产品接口与宿主预设。

README顶部明确本地命令执行、图片读取和持续wait能力前提，提前呈现App/CLI→skill安装与验证→连接三步。通用安装显式指定宿主认可的技能父目录，说明生成teach-me/SKILL.md、status检查、更新/重载；也提供手动复制和不支持skill加载时直接读取指引/CLI协议的路径。Codex只在可选预设中出现，不臆造其他Agent目录或宣称未经验证的宿主可自动发现技能。

本条修正ADR-019的公开文档默认叙述，保留现有setup的Codex快捷行为及默认目录兼容性，单独说明其作用；不为文案反馈引入新的自动探测/安装行为。CLI帮助和安装完成提示采用通用技能措辞，具体预设仍准确标注。能力兼容、文件复制、宿主发现与真实教学分别验收，见T25。

## ADR-022 · 接受 · 2026-10-19 · 一句话委托Agent安装

用户指出T25把install/path/status列成三行，看起来都必须执行，并要求“让Agent读取xxx然后安装”的一句话入口。README推荐方式改为在当前仓库上下文中把一句安装请求交给Agent，指向随Git维护的INSTALL.md；由Agent读取指南、确认其宿主的技能目录、执行安装并报告结果，用户不必先理解目录和诊断命令。

INSTALL.md是安装指南，不是运行教学skill；不在安装后自动开始教学或申请截图。手动安装保留一条install主命令，path/status移到明确可选的检查区；Codex仍只作可选预设。指南进入项目记忆源摘要和链接检查，不虚构尚未发布的远程安装地址，不把本地文件/命令验证说成独立Agent验收。本条调整ADR-021的默认呈现，保留通用CLI与宿主边界，见T26。

## ADR-023 · 接受 · 2026-10-19 · 主动视觉取证与可替换消息接收

用户结束快速试用后指出Agent几乎不主动capture，且wait应只是兜底。旧skill把优先用户图、回复后回wait写成固定循环，capture只有附带一句；这容易把过期图当作当前状态，并把教学策略绑定到长轮询。修正为先判断视觉证据是否足够，再给指引，再按已验证的接收策略收消息。

需要当前界面而无足够新画面、操作后布局未知、指引被纠正或出现弹窗/错误时，Agent主动请求capture，打开shot.path再判断；新用户截图足够时复用，小目标用zoom。语义问题不无谓取图，不按固定间隔抓屏，截图拒绝后不循环申请。

原生唤醒优先，但必须有TMA→正确Agent会话→实际开始/继续处理的已配置、已验证链路；生命周期hook或完成通知本身不算。当前实现只有CLI队列/ack/长轮询，未交付原生适配器，因此目前仍使用wait兜底。仅修改skill不会启用唤醒；原生投递后才可退出长等待，切换必须保留同会话、去重、ack与健康状态。研究及后续边界见[HOST-INTEGRATION.md](HOST-INTEGRATION.md)，T27修订规则，T28负责真实适配器。

本条修正ADR-021/022中将持续wait视为通用能力前提的描述，保持只指不代操作、截图审批、单输入面与Agent无关协议；不自动修改用户hook或创建新的教学Agent。

## ADR-024 · 接受 · 2026-10-19 · Agent自主选择接收机制

用户在六种宿主调查后明确要求“让agent自己决定是否用hook，就不对具体agent说明了”。通用skill只给目标与必要约束，由Agent根据当前环境选择接收方式；可以复用现有通路，也可以按需使用受支持的会话级设施接通hook/事件通道，不再规定必须预装专用桥或把配置另开任务。六家接口对照保留为工程历史研究，不成为教学必读指引，也不预设逐家开发适配器。

本条细化R33并以R34取代ADR-023中“只能依赖已配置的桥”和不可在教学时配置的限制。保留真正可达当前对话、空闲触发处理、可靠接收后确认、单消费者交接与结束清理；无法接通、无法验证或接入不合适时继续wait。安装skill本身不会启用hook，规则修改也不等同于唤醒链路已实现。

T29交付通用规则与安装副本同步；T28改为按实际需要补齐通用接收/ack/健康能力并验收Agent所选通路，不默认维护每家宿主的配置脚本。原生验收仍待实际实验；不因自主选择策略就声称CLI已提供可靠后台转发。

## ADR-025 · 接受 · 2026-10-20 · 退出不依赖清理成功

用户要求普通Windows用户遇到异常也能恢复。实际故障注入确认：退出先设置quitting，再等待语音取消所触发的窗口样式/焦点恢复；恢复拒绝会跳过会话结束与退出，重复stop又假成功。该故障独立于T14尚未复现的静置退出。

退出共用一个清理Promise，先结束会话与待处理请求，跳过无意义的退出焦点恢复；各清理步骤独立捕获并只记录安全错误元数据。endpoint删除失败仍正常退出，下一次启动覆盖旧endpoint；整体超过5秒记录超时并以非零码退出。重复原生关闭和app.quit不绕过清理，新HTTP/IPC业务操作拒绝；正常stop响应留100ms刷新时间。不引入自动重启或会话持久化，不宣称未发送草稿和画板可跨进程恢复。验收见A35/T30。

## ADR-026 · 接受 · 2026-10-20 · 发送提交不由焦点恢复回滚

连续使用验收发现投递和restore共用catch：消息已经入队，恢复失败又开放旧turn；修改后重试被Session按clientId去重，UI却清稿。现在把投递作为提交边界，恢复失败只提示已发送，不要求用户重发；真正投递失败仍保留原turn与截图。延迟恢复不能覆盖新turn，延迟IPC回包不能清除已变更的草稿或移走新turn焦点。Renderer只增加提交草稿版本保护，保持单一输入面与原去重机制，不引入新会话层。来源为本轮实际故障注入及独立审查，见A05/T31。

## ADR-027 · 接受 · 2026-10-20 · 主面板崩溃有界恢复

依据用户授权的异常恢复目标与真实故障注入：panel renderer退出会留下仍占单实例锁的宿主，重复启动不能得到可用面板。宿主保留已提交消息和待ack队列，只重载原panel BrowserWindow的本地UI，取消旧输入、语音和未完成审批；不重载健康overlay或自定义HTML。未发送草稿/录音不承诺恢复，界面明确提示重新输入。

60秒内仅自动恢复一次；第二次故障、重载拒绝或10秒内未完成本地UI与桥接握手，进入T30有界清理并退出1，用户可重新启动。采用有限窗口重载，避免增加后台重启器或跨进程会话持久层。进程退出仍结束内存会话；本决议不扩大为主进程/GPU崩溃恢复，也不将T14历史退出判定为已定位。

恢复期间拒绝新的输入/审批业务，wait/ack/say继续；旧输入、语音提交、IPC错误及快捷键回调不得污染恢复后的新输入。恢复诊断仅含角色、原因、退出码等元数据。实现与证据见[T32](evidence/T32.md)。

## ADR-028 · 接受 · 2026-10-20 · Windows helper按进程代次结算

T32期间首次启动原生适配曾等待约10秒失败，现有错误不能区分helper未启动、退出、响应超时或原生拒绝。独立调查又复现旧helper迟到exit和半行stdout破坏替换进程的请求；这两项有确定证据，但不作为该次首次启动超时的根因。

WindowsAdapter使每个helper拥有自己的pending、stdout缓冲与closed标记，dispose立即结算本代请求，旧事件不触碰新代。超时废弃本代，下一请求可创建新进程；不自动重试已经可能执行的窗口写操作。PowerShell完成Add-Type后报告ready，启动错误终止、请求错误明确返回；stderr只排空并统计字节数。固定失败码和脱敏日志记录kind、reason、代次、耗时、ready及exitCode，不写句柄、命令或原始stderr。单次启动偶发失败须依新诊断继续追踪，见[T33](evidence/T33.md)。

## ADR-029 · 接受 · 2026-10-20 · 面板按工作区容量排版

短工作区实际复现：原生窗口已收紧到480 DIP，页面仍排到560 CSS px，底部锚定使标题移到-79px。宿主按面板所在显示器提供独立高度容量，Renderer用它限制自然布局；禁止直接用当前100vh限制测高，否则从48px胶囊展开会受自身旧高度约束。沿用ADR-018的自然测高、版本校验与合成层动画。

窗口容量缩小时，长草稿减少可见行数并内部滚动，给标题、工具和可滚动审批保留空间。高度回报由CSS换算为DIP，发往Renderer的动效几何换算为CSS；页面zoom测试与Windows DPI/真实短工作区证据分别记录，不由对话档通过推定任意页面缩放或三档都已验收。未改变全局显示器配置。见T02/[桌面证据](evidence/DESKTOP-001.md)。

## ADR-030 · 接受 · 2026-10-20 · 连接审批随请求取消

真实CLI在start审批中退出后，旧审批仍可创建会话，却没有客户端收到凭据，重试被活跃会话阻挡。将待连接审批与选屏绑定原HTTP请求：响应连接在提交前关闭就撤销自身请求；在异步原生取消后再次检查，避免批准到提交之间的断连仍创建会话。attach取消保留原Session和消息。旧选屏动作经过等待后核对请求身份，不能作用于替代请求。

沿用现有审批、Session与CLI凭据保存边界，不增加持久化事务或自动重连层。创建Session与返回结果之间没有异步等待；提交后的响应丢失不能保证客户端已接收，但不因此回滚活跃教学，调用方通过status/attach恢复。范围与真实CLI证据见[T36](evidence/T36.md)，多屏请求模拟不代表真实多屏几何验收。

## ADR-031 · 接受 · 2026-10-22 · 只读helper超时不缩短窗口写操作期限

补充ADR-028：用户检视及FakeChild对照确认，3秒fg/down超时会通过close整代helper提前结束10秒input/style。fg/down/style只读查询超时现在只结算自身并进入draining；已登记请求保留原期限，draining不向旧代写入新命令，也不启动替代helper并发修改窗口。新请求返回NATIVE_HELPER_RECOVERING（查询返回null/false，窗口方法提示稍后重试），剩余pending结束即淘汰；持续轮询不能延长期限。

activate/input自身超时仍立即淘汰整代，避免已向调用方报告失败的写操作继续排队并迟到抢焦点/改样式；不重放可能已执行的操作。不能仅把所有期限加长、无限保留卡死helper或为未退出的旧写操作立即启动并行helper。kill调用不是已确认原生进程退出，实际Windows慢启动与窗口操作仍待验收，见[T41](evidence/T41.md)。
